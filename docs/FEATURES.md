# 기능 명세

각 기능은 "수용 기준"을 모두 통과해야 완료다. 수치 기준(파일 크기, 길이 등)은 초안이며, 확정값은 `docs/DECISIONS.md`에 기록한다.

---

## F1. 사진 리사이즈·크롭

처리 위치: 브라우저 (Web Worker + OffscreenCanvas, 미지원 브라우저는 메인 스레드로 폴백)

입력

- JPG, PNG, WebP (HEIC는 F10)
- 최대 파일 크기 초안: 30MB

조절 방식

- 크기 직접 입력 (px), 비율 고정·해제
- 맞춤 방식 (화면 이름)
  - 꽉 채우기: 비율에 맞게 잘라서 화면을 꽉 채운다. 크롭 위치는 드래그로 조절
  - 배경 채우기: 사진 전체를 넣고, 남는 곳은 배경으로 채운다 (아래 "배경 채우기" 참고)
  - 늘이기: 비율을 무시하고 늘인다
- 회전, 좌우 반전

배경 채우기 (배경화면용, M1)

폰 배경화면으로 설정하면, 화면보다 가로가 넓은 사진은 세로를 화면에 맞추려고 확대되면서 양옆이 잘린다. 세로 사진이어도 화면(예: 1170x2532는 약 9:19.5)보다 가로가 넓으면 그렇고, 정사각형 사진은 가운데만 크게 확대돼 보인다. 배경 채우기는 사진을 자르지 않고 화면에 맞는 배경화면 파일을 만든다.

- 사진의 가로를 목표 가로(예: 1080, 1440)에 맞춰 비율 그대로 줄이거나 키운다. 목표 세로에서 모자라는 만큼 위아래를 배경으로 채운다. 가로로 긴 화면(태블릿 가로 등)이면 양옆을 채운다
- 배경 종류 (AI 없이 브라우저에서. AI로 새로 그려 채우기는 M6의 F22)
  - 자연스럽게 (기본): 밝기·색은 경계 근처에서 사진 가장자리 색을 잇고 멀어질수록 가로로 고르게 퍼지게 해서 세로 줄무늬가 생기지 않게 한다. 그 위에 경계 쪽 사진 띠의 결(대리석 무늬·노이즈)을 무작위 조각으로 이어 붙여 더한다. 타일 줄눈 같은 가는 선과 빛 반사처럼 튀는 조각은 뺀다. 사진에 없던 물체나 구조는 그리지 못한다 (AI는 F22)
  - 가장자리 늘이기: 사진 가장자리 줄을 바깥으로 늘이고, 사진 가까이는 덜 흐리게·멀수록 많이 흐리게 해서 이어 붙인다. 가장자리 줄을 그대로 늘이면 무늬가 커튼 같은 줄무늬가 되므로 줄 방향으로 뭉갠 뒤 늘인다. 하늘처럼 결이 거의 없는 배경에 어울린다
  - 흐린 사진: 같은 사진을 화면에 꽉 차게 키워서 흐리게 깐다. 인물 사진은 뒤에 큰 흐린 얼굴이 비친다
  - 거울 반사: 가장자리에서 사진을 뒤집어 이어 붙인다. 풍경·물가 사진에 어울리고 인물 사진에는 어색하다
  - 비슷한 색: 사진 위·아래 가장자리의 평균 색으로 채운다
  - 단색: 검정, 흰색, 직접 고른 색
  - 흐림 정도와 어둡게 하기는 사진을 쓰는 배경(늘이기·흐린 사진·거울)에서 조절할 수 있다
- 사진 경계를 부드럽게 섞기 (기본 켬): 사진 가장자리를 배경 쪽으로 서서히 투명하게 해서 경계선이 보이지 않게 한다
- 사진 위치: 기본은 자동이다. 사진 가장자리가 얼마나 복잡한지 재서, 사람·물건이 걸쳐 잘린 쪽(복잡한 쪽)은 화면 끝에 붙이고 벽·하늘처럼 단순한 쪽만 채운다. 잘린 팔다리를 늘이면 팔다리가 늘어난 것처럼 보이기 때문이다. 양쪽이 비슷하면 가운데에 둔다. 끌어서 옮길 수 있다 (잠금화면 시계가 얼굴을 가리지 않게)
- 사진 크기: 100%(사진 전체)부터 꽉 채우기와 같아질 때까지 키울 수 있다. 키우면 반대쪽(위아래를 채울 땐 양옆)이 조금 잘리는 대신 채울 곳이 줄어 더 자연스럽다
- 사진 비율이 기기 화면과 다르면 미리 알려준다: "이 사진은 화면보다 가로가 넓어서 양옆이 잘려요. 배경 채우기로 사진 전체를 넣을 수 있어요"
- 사진 가로가 목표 가로보다 작으면 확대가 필요하다. 아래 "확대" 안내가 함께 나온다
- 큰 사진에서 원하는 부분만 잘라 쓰는 것은 "꽉 채우기"(크롭)에서 한다

출력

- JPG(화질 조절), PNG, WebP
- 파일명: `원본이름_기기또는크기_가로x세로.확장자`
- 고품질 축소: 저장할 때 줄이는 경우 pica Lanczos3 (ADR-026)
- 카카오톡 같은 앱 안의 브라우저(인앱 브라우저)는 페이지가 만든 파일을 내려받지 못하는 경우가 많다 (ADR-027)
  - 인앱 브라우저로 열리면 맨 위에 "다른 브라우저로 열기" 안내를 띄운다. 사진을 고르기 전에 옮기게 한다
  - 안드로이드 인앱 브라우저: 저장 버튼을 누르면 파일 대신 다른 브라우저로 열라는 안내를 보여준다
  - iOS 인앱 브라우저: data URL로 내려받는다

확대 (업스케일 기본, M1)

- 목표 크기가 원본보다 크면 브라우저 고품질 보간으로 확대한다. 줄여서 저장할 때는 Lanczos3(pica)로 줄여서 브라우저마다 화질이 같다 (ADR-026)
- 확대 배율을 알려준다: "원본보다 2.3배 커요. 흐려 보일 수 있어요"
- AI로 더 선명하게 키우는 기능은 F20 (M3)에서 한다. F20이 준비되면 이 안내에서 바로 이어 쓸 수 있게 한다

수용 기준

- [ ] 4000x3000 사진을 "꽉 채우기"로 1170x2532에 맞추면 결과가 정확히 1170x2532다
- [ ] 900x1200 사진을 "배경 채우기"로 1170x2532에 맞추면, 결과는 1170x2532이고 사진은 잘리지 않고 1170x1560으로 들어가며 위아래가 486px씩 배경으로 채워진다
- [ ] 1440x1440 사진을 "배경 채우기"로 1170x2532에 맞추면 사진이 1170x1170으로 들어가고 위아래가 681px씩 채워진다
- [ ] 배경 채우기에서 사진 비율이 바뀌지 않는다 (늘어나거나 눌리지 않음)
- [ ] 사진이 기기 화면보다 가로가 넓으면 "양옆이 잘려요" 안내와 배경 채우기 제안이 보인다
- [ ] 위는 벽이고 아래에서 사람이 잘린 사진을 배경 채우기 하면, 사진이 화면 아래에 붙고 위만 채워진다
- [ ] 3024x4032 사진을 1440x3200에 사진 크기 130%로 맞추고 아래에 붙이면, 사진은 1872x2496(양옆 216px씩 잘림)이고 위 704px만 채워진다
- [ ] 1000x750 사진을 2000x1500으로 키우면 결과가 정확히 2000x1500이고, 확대 배율 안내가 보인다
- [ ] 세로로 찍은 사진이 눕지 않는다 (EXIF 방향 반영)
- [ ] 위치정보(GPS) 등 메타데이터가 기본으로 제거된다
- [ ] 처리 중에도 화면이 멈추지 않는다
- [ ] 사진 작업 중 네트워크 탭에 이미지 업로드 요청이 없다 (보관에 동의한 경우 제외, F16)

## F2. 기기 프리셋

데이터 구조와 검증 규칙은 `docs/PRESETS.md`를 따른다.

- 카테고리: 폰, 폴더블(접은 화면·펼친 화면), 플립(메인·커버 화면), 태블릿, 워치
- 검색: "16 프로", "폴드6", "워치7"처럼 입력하면 바로 찾는다 (aliases 사용). 검색 결과가 없으면 검색어를 이벤트로 남겨 프리셋 추가 우선순위에 쓴다
- 최근 사용 기기와 "내 기기" 저장 (localStorage, 로그인 없음)
- 프리셋을 고르면 크롭 박스 비율이 고정되고 화면 모양 가이드가 보인다
  - rect: 일반 사각형
  - rounded-rect: 둥근 사각형 (애플워치 등)
  - circle: 원형 (갤럭시 워치 등)
- 원형 워치 출력: 정사각형 이미지에서 원 밖을 검정으로 채우거나 투명(PNG)으로 둘 수 있다
- 워치 움짤 형식은 기기마다 다르다: 갤럭시 워치는 GIF, 애플워치는 Live Photo (F3 참고)

수용 기준

- [ ] `verified: true`인 프리셋만 사용자에게 보인다
- [ ] 폴드·플립은 내보낼 화면을 고를 수 있다
- [ ] 원형 워치 프리셋에서 원 바깥 영역이 미리보기에 표시된다
- [ ] "내 기기"가 새로고침 후에도 유지된다

## F3. 영상 → GIF·WebP·MP4

처리 위치: 서버. 작업 크기에 따라 Lambda 또는 Fargate Spot (`docs/ARCHITECTURE.md`)

입력

- MP4, MOV, WebM
- 원본 최대 크기 초안: 500MB (하이라이트용 녹화 파일은 별도 기준, `docs/HIGHLIGHT.md`)
- 내보낼 구간 최대 길이 초안: 움짤 30초, 클립(MP4) 3분

출력 형식

- GIF: 호환성이 가장 좋지만 용량이 크다
- 애니메이션 WebP: 같은 화질에 더 작다
- MP4 (무음 반복용): 가장 작다

워치용 움짤

- 갤럭시 워치: 워치 화면 크기의 GIF
- 애플워치: 사진 워치 페이스는 Live Photo를 움직이게 보여준다. 1차로는 워치용 짧은 MP4를 만들고 Live Photo로 바꾸는 방법을 안내한다. 웹에서 Live Photo(정지 이미지 + 짧은 영상 묶음)를 바로 만들어 아이폰 사진 앱에 저장하는 방법은 조사 과제다 (M6)

옵션 (기본값만으로 좋은 결과가 나오게 하고, 나머지는 "고급"에 접어둔다)

- 크기: 직접 입력 또는 프리셋 (워치용, 움짤 가로 폭 480·640, 기기 화면)
- 크롭 비율: 원본, 1:1, 9:16, 16:9, 기기 비율
- FPS 10~30 (기본 15), 재생 속도 0.5x~2x, 반복 여부
- GIF 화질: ffmpeg 팔레트 생성 2단계(palettegen → paletteuse), 디더링 선택

수용 기준

- [ ] 만들기 전에 예상 용량이 보인다 (실제와 ±30% 이내)
- [ ] 결과의 시작·끝이 미리보기에서 고른 구간과 1프레임 이내로 일치한다 (재인코딩으로 자르므로 키프레임 위치에 밀리지 않는다)
- [ ] 업로드, 대기, 처리 진행 상황이 보이고 업로드는 취소할 수 있다
- [ ] 실패하면 이유와 해결 방법이 보인다 (예: "영상이 너무 길어요. 30초 이하 구간을 골라주세요.")
- [ ] 원본과 결과 파일이 수명 주기 규칙으로 자동 삭제된다 (보관 동의 파일 제외)

## F4. 타임라인 구간 선택

움짤(F3), 음성(F14), 링크 구간(F15), 하이라이트 후보 다듬기(F6)가 같은 타임라인 컴포넌트를 쓴다.

- 미리보기는 업로드를 기다리지 않는다. 고른 파일을 브라우저에서 바로 재생(Object URL)하고, 업로드는 뒤에서 진행한다
- 썸네일 스트립: 브라우저에서 video를 돌며 추출. 음성 도구에서는 썸네일 대신 파형을 보여준다
- 링크 구간에서는 같은 타임라인이 유튜브 공식 플레이어를 API로 제어한다
- 시작·끝 핸들 드래그, 구간 주변 확대·축소
- 시간 직접 입력 (분:초.밀리초)
- 선택 구간 반복 재생
- 키보드
  - ← / →: 1프레임 이동
  - Shift + ← / →: 1초 이동
  - I / O: 현재 위치를 시작 / 끝으로 지정
  - Space: 재생·정지, L: 구간 반복 켜기·끄기
- 모바일: 큰 핸들, 확대 슬라이더, ±1프레임 버튼
- 프레임 단위 이동에는 영상 FPS가 필요하다. 업로드 직후 서버의 ffprobe 결과로 받을지, 브라우저에서 파싱할지는 DECISIONS에서 정한다. 지원 브라우저에서는 requestVideoFrameCallback으로 정확한 프레임 시각을 쓴다

수용 기준

- [ ] 키보드만으로 구간을 고르고 내보낼 수 있다
- [ ] 폰에서 0.1초 단위로 구간을 조절할 수 있다
- [ ] 파일을 고른 직후, 업로드 완료를 기다리지 않고 미리보기가 된다

## F7. 잠금화면·워치 미리보기

- 결과를 기기 모양 위에 보여주고, 시계·위젯·카메라 위치를 반투명으로 겹쳐 보여준다
- 위치값은 프리셋의 `overlays` (대략적인 가이드값)를 쓰고, 화면에도 "대략적인 위치"라고 표시한다

수용 기준

- [ ] 오버레이를 켜고 끌 수 있다
- [ ] `overlays` 데이터가 없는 기기는 오버레이 버튼이 보이지 않는다

## F8. 여러 기기 한 번에

- "내 기기 세트"를 고르면 사진 하나로 기기별 결과를 만든다
- 기기마다 크롭 위치를 따로 조절할 수 있다
- 브라우저에서 ZIP으로 묶는다 (fflate 등)

수용 기준

- [ ] 기기 3개 세트를 ZIP 파일 하나로 받는다
- [ ] 파일명에 기기 이름이 들어간다

## F9. 목표 용량 맞추기

- "200KB 이하"처럼 목표를 정하면 화질(필요하면 크기)을 이진 탐색으로 낮춰 맞춘다
- 서류 업로드 규격(증명사진 등) 프리셋을 둔다

수용 기준

## F14. 음성 추출·벨소리

처리 위치: 서버 Lambda (음성 작업은 가볍다)

- 입력: MP4, MOV, WebM, M4A, MP3, WAV (원본 최대 500MB 초안)

- 옵션: 페이드 인·아웃, 음량 맞추기(라우드니스 정규화), 모노·스테레오, 비트레이트

수용 기준

- [ ] 페이드 인·아웃이 적용된다
- [ ] 벨소리 프리셋에서 길이 제한을 넘으면 안내한다

## F15. 링크 구간 저장·반복 재생

영상 파일을 만들지 않는다. 공식 임베드 플레이어로 재생하고, 링크와 구간 정보만 저장한다.

- 지원: YouTube (1차). 다른 플랫폼은 공식 임베드 플레이어와 약관을 확인한 뒤 추가한다
- 흐름: 링크 붙여넣기 → 영상 ID 추출 → YouTube IFrame Player API로 재생 → F4 타임라인으로 구간 선택 → 저장
- 결과
  - FitCut 구간 반복 링크: 열면 그 구간만 반복 재생되는 페이지
  - 유튜브 시작 시점 링크 (공유용)
  - "내 구간" 목록 (이 브라우저에 저장, 서버에는 링크·구간만)
- 임베드 기본 파라미터의 시작·끝은 초 단위다. 더 세밀한 반복은 플레이어 API로 현재 시간을 확인해 처리한다
- 소유자가 다른 사이트 재생을 막아둔 영상은 오류 코드를 받아 안내한다: "이 영상은 다른 사이트에서 재생할 수 없게 설정돼 있어요"
- YouTube API 서비스 약관과 개발자 정책을 따른다 (플레이어 위에 UI를 겹치지 않기, 최소 크기 등)
- 하지 않는 것: 영상·음성 파일 저장, GIF 변환, 화면 캡처

수용 기준

- [ ] 링크 구간 작업 중 영상 데이터가 FitCut 서버를 거치지 않는다
- [ ] 구간 반복 링크를 열면 시작부터 끝까지 반복 재생된다
- [ ] 임베드가 막힌 영상에서 안내 문구가 나온다
- [ ] 저장된 구간이 관리자 화면의 링크 통계에 잡힌다

## F16. 작업 파일 보관 (동의한 경우만)

- 기본: 업로드·결과 파일은 수명 주기로 1~2일 안에 자동 삭제
- 업로드·저장 화면에 선택 항목: "작업 파일을 30일 동안 보관하기" (기본 꺼짐, 목적과 기간 안내)
- 동의하면 원본과 결과를 보관 버킷(SSE-KMS)으로 옮기고, 30일 후 자동 삭제한다
- 사진 도구는 원본을 올리지 않는다. 동의한 경우에만 결과 이미지를 올려 보관한다
- 사용자는 "내 작업 기록"(이 브라우저에 저장된 작업 목록과 삭제 토큰)에서 언제든 삭제할 수 있다
- 관리자는 관리자 화면에서 보관 파일을 볼 수 있고, 볼 때마다 감사 로그에 남는다

수용 기준

- [ ] 동의하지 않은 파일은 보관 버킷에 들어가지 않는다
- [ ] 사용자가 삭제하면 원본·결과가 바로 지워지고 관리자 화면에서도 사라진다
- [ ] 관리자 열람이 감사 로그에 기록된다

## F20. AI 업스케일 (M3)

작은 사진을 2배·4배로 선명하게 키운다. 기본 확대(보간)는 F1에 있다.

처리 위치: 브라우저 (WebGPU, 안 되면 WebAssembly). 사진을 서버로 보내지 않는다는 원칙을 지킨다 (ADR-023).

- 배율: 2x, 4x
- 입력 상한 초안: 결과의 긴 변이 4096px 이하. 메모리를 아끼려고 이미지를 타일로 나눠 처리한다
- 모델: Real-ESRGAN 계열, Swin2SR 등을 후보로 본다. 코드와 가중치 각각의 라이선스, 모델 파일 크기, 폰·PC 처리 속도를 확인해 ADR-023에서 고른다. TODO(verify)
- 모델 파일은 처음 쓸 때만 내려받아 브라우저에 캐시한다 (앱 번들에 넣지 않는다). 모델 크기 × 내려받은 횟수만큼 CloudFront 전송량이 늘어나므로 비용 추정에 넣는다
- 진행률과 취소를 보여준다. 처리는 Web Worker에서 해서 화면이 멈추지 않는다
- WebGPU가 없거나 너무 느린 기기에서는 "이 기기에서는 오래 걸려요" 안내를 띄우거나, 기본 확대(F1)를 권한다

수용 기준

- [ ] 500x500 사진을 2x로 키우면 결과가 정확히 1000x1000이다
- [ ] 처리 중 네트워크 탭에 이미지 업로드 요청이 없다 (모델 파일 다운로드만 있다)
- [ ] 처리 중에도 화면이 멈추지 않고, 취소할 수 있다
- [ ] 1000x1000 → 2x 처리 시간을 PC와 폰에서 측정해 README에 남긴다

## F21. 영상 세로로 돌리기 (M3)

누워 있는 가로 영상을 90° 돌려 세로 영상으로 만든다. 해상도와 프레임은 그대로 두고 가로·세로만 바꾼다 (예: 1920x1080 30fps → 1080x1920 30fps). 화면을 돌리기만 하고, 자르거나 배경을 채워 세로 화면에 맞추는 기능은 아니다.

처리 위치: 서버. 움짤과 같은 ffmpeg 워커를 쓰고, 작업 크기에 따라 Lambda 또는 Fargate Spot으로 보낸다 (ADR-002).

- 입력: MP4, MOV, WebM. 원본 최대 크기는 F3과 같다 (초안 500MB). 영상 길이 상한 초안 10분
- 방향: 오른쪽 90°, 왼쪽 90°, 180°. 좌우 반전도 함께 고를 수 있다
- 유지하는 것: 해상도(가로·세로만 바뀜), 프레임 수와 타임스탬프(가변 프레임 영상 포함), 음성 트랙(재인코딩 없이 복사)
- 방식 두 가지를 M3에서 측정해 기본값을 정한다 (ADR-024)
  - 재인코딩 회전: 실제 픽셀을 돌린다. 어떤 앱에서도 세로로 보이지만, 시간이 걸리고 다시 압축하면서 화질이 조금 떨어질 수 있다. 화질 손실이 눈에 띄지 않게 품질 값을 높게 잡는다
  - 회전 정보만 바꾸기: 다시 압축하지 않아 몇 초 만에 끝나고 화질 손실이 없다. 다만 회전 정보를 무시하는 앱·편집기에서는 가로로 보일 수 있다
- 폰으로 찍은 영상은 이미 회전 정보가 들어 있는 경우가 많다. 미리보기에서 보이는 방향을 기준으로 돌린다
- HDR·10비트 원본(최근 아이폰 등)을 어떻게 처리할지(그대로 유지 또는 SDR 변환)는 구현 때 확인한다. TODO(verify)

수용 기준

- [ ] 1920x1080 30fps 영상을 오른쪽 90°로 돌리면 결과가 1080x1920 30fps이고, 프레임 수와 길이가 원본과 같다 (±1프레임)
- [ ] 음성이 원본과 같은 코덱·길이로 남는다
- [ ] 회전 정보가 들어 있는 폰 영상도 미리보기에서 본 방향 기준으로 돌아간다
- [ ] 두 방식의 처리 시간과 잡당 비용이 README에 기록된다

## F22. AI 배경 채우기 (M6)

배경 채우기(F1)에서 남는 곳을 생성형 AI로 새로 그려 채운다. 예: 사진을 조금 키워 아래에 붙이고, 위쪽 벽의 무늬·타일·조명을 이어서 그린다. AI 없는 배경(가장자리 늘이기 등)은 벽·하늘이 단순한 사진에서는 자연스럽지만, 무늬 있는 벽은 매끈하게만 이어진다.

처리 위치: 서버 (Bedrock). 사진 도구에서 유일하게 사진이 기기를 떠나는 기능이라, 기본 흐름에 넣지 않고 사용자가 고를 때만 쓴다 (ADR-025).

- 사용자가 "AI로 채우기"를 누를 때만 사진을 보낸다. 누르기 전에 "이 기능은 사진을 서버로 보내 처리하고, 처리 후 바로 지워요"와 처리 지역을 알린다
- 보내는 사진은 목표 크기에 맞게 줄인 사본이다. EXIF·위치정보는 브라우저에서 지운 뒤 보낸다
- 서버는 사진을 저장하지 않는다 (S3에 쓰지 않고 메모리에서 처리). 로그에 사진 내용을 남기지 않는다
- 결과 중 원래 사진 영역은 브라우저에서 원본으로 다시 덮어 화질을 지킨다. AI가 그린 곳만 쓴다
- 남용 방지: IP 해시별 하루 횟수, 서비스 전체 하루 상한, 상한에 닿으면 AI 없는 배경으로 안내. Budgets 알림
- 모델·리전·가격은 M6 시작 때 다시 확인한다. 2026-10-10 기준 Bedrock에서 쓸 수 있는 것은 Stability AI Outpaint(미국 리전)뿐이다. TODO(verify)

수용 기준

- [ ] "AI로 채우기"를 누르기 전에는 업로드 요청이 없다 (네트워크 탭)
- [ ] 결과 크기가 목표와 같고, 원래 사진 영역은 원본과 같은 화질이다
- [ ] 하루 상한을 넘으면 요청이 거절되고 AI 없는 배경 안내가 보인다
- [ ] 장당 비용과 처리 시간이 README에 기록된다
