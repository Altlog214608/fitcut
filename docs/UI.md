# UI/UX

## 원칙

1. **시작은 하나.** 첫 화면은 큰 드롭 영역과 링크 입력칸이다. 넣은 것을 보고 알맞은 도구를 연다.
   - 사진 → 사진 도구
   - 영상 → "무엇을 만들까요?" (움짤, 음성, 세로로 돌리기) 중 고르기
   - 음성 파일 → 음성 도구
   - 유튜브 링크 → 링크 구간
   - 방송 하이라이트는 채널 연결이 필요하므로 별도 입구로 둔다
2. **한 화면에 한 작업.** 흐름은 올리기 → 맞추기 → 내보내기 세 단계다.
3. **기본값으로 충분하게.** FPS, 화질, 디더링 같은 옵션은 "고급"에 접어둔다.
4. **모바일 우선.** 폰 배경화면은 폰에서 만드는 경우가 많다. 엄지로 잡기 쉬운 핸들, 하단에 고정된 저장 버튼.
5. **광고·회원가입·워터마크 없음.** 첫 화면에서 분명하게 보이게 한다.
6. **신뢰를 주는 문구.**
   - 사진 도구: "사진은 이 기기 밖으로 나가지 않아요"
   - 움짤·음성 도구: "올린 파일은 보통 1~2일 안에 자동으로 삭제돼요"
   - 링크 구간: "영상은 유튜브에서 재생되고, 링크와 구간만 저장돼요"

## 디자인 방향 (2026-10-09 확정)

방향은 "토스처럼 담백하게"다. 다만 토스 고유의 색과 서체는 쓰지 않는다. 사진·영상을 다룬다는 느낌은 선 아이콘과 드롭 영역의 작은 그림으로만 준다.

- 기억에 남는 요소는 하나만 둔다: **실제 기기 모양 미리보기** (폰 프레임, 둥근 사각형·원형 워치 화면). 잘리는 바깥은 어둡게 눌러 보여준다. 나머지는 조용하고 단정하게.
- 흔한 템플릿 느낌을 피한다: 똑같은 둥근 카드 나열, 장식용 그라데이션, 모든 제목 위에 붙는 영문 대문자 라벨, 순서가 아닌 내용에 붙인 번호.
- 접근성: 키보드로 모든 조작 가능, 포커스 표시(포인트 색 2px 테두리), 글자 대비 4.5:1 이상, `prefers-reduced-motion` 존중.
- 움직임은 사용자 동작에 대한 반응(변환 완료, 시트 열림)에만 200ms 이하로 쓴다.
- 다크 모드는 기기 설정을 따른다.

### 색

회색은 살짝 푸른 쪽으로 기울였다. 포인트 색은 주 버튼, 크롭 핸들, 선택된 항목에만 쓴다. 오류 빨강은 포인트 색과 따로 둔다.

| 토큰 | 이름 | 라이트 | 다크 | 쓰는 곳 |
| --- | --- | --- | --- | --- |
| `ink` | 잉크 | `#171A1F` | `#F2F4F6` | 제목, 본문 (바탕 대비 17:1) |
| `slate` | 슬레이트 | `#5B6470` | `#9AA3AE` | 보조 글자, 아이콘 (대비 6:1 이상) |
| `line` | 라인 | `#E3E7EC` | `#2B3038` | 구분선, 테두리 |
| `paper` | 페이퍼 | `#F4F6F8` | `#1A1D22` | 미리보기 바탕, 입력칸 |
| `bg` | 바탕 | `#FFFFFF` | `#101215` | 화면 바탕 |
| `accent` | 포인트(블루) | `#2B63F0` | 버튼 `#2B63F0`, 글자 `#6E9BFF` | 주 버튼(흰 글자 대비 5.07:1), 크롭 핸들, 선택 |

### 서체

- 한 가족만 쓴다: **Pretendard** (SIL OFL 1.1). 앱에 직접 넣고 외부 폰트 서버를 부르지 않는다 (ADR-022).
- 단계: 제목 26/740, 소제목 20/700, 본문 16/400, 보조 14/500. 해상도·시간·용량 숫자는 16/650에 고정폭 숫자(`tabular-nums`).
- 제목은 글자 간격을 살짝 좁힌다 (-0.02em).

### 아이콘과 그림

- **Lucide** 선 아이콘 (ISC), 굵기 1.75. 도구 입구에서는 `accent-soft` 바탕의 40px 타일 안에 넣고, 나머지는 선만 둔다.
- 그림은 드롭 영역 한 곳에만 둔다. 사진 한 장이 워치와 폰 모양으로 맞춰지는 장면이다. 3D 그림이나 장식용 그라데이션은 쓰지 않는다.
- 예시 사진은 직접 찍었거나 라이선스가 확인된 것만 쓴다.

### 레이아웃

- 카드를 늘어놓지 않는다. 목록, 여백, 얇은 선으로 나누고, 테두리와 그림자는 기기 미리보기와 아래 시트에만 쓴다.
- 간격은 8px 단위, 모바일 좌우 여백 20px. 글 폭은 최대 680px, 도구 화면은 최대 1200px.
- 주 버튼은 화면에 하나. 모바일에서는 아래에 고정한다 (높이 52~56px).
- 둥글기: 버튼·입력칸 12~14px, 아래 시트 20px. 기기 프레임은 실제 기기 비율과 모양을 따른다.

## 문구 규칙

- 사용자 관점의 쉬운 말을 쓴다: "인코딩" 대신 "만들기", "잡 실패" 대신 "변환하지 못했어요".
- 버튼은 결과를 말한다: "GIF 만들기", "ZIP으로 저장", "구간 저장". 같은 동작은 끝까지 같은 이름을 쓴다.
- 오류는 무엇이 문제이고 어떻게 고치는지 말한다: "영상이 너무 길어요. 30초 이하 구간을 골라주세요."
- 빈 화면은 행동을 권한다: "예시 영상으로 해보기"
- 동의 문구는 짧고 구체적으로: 무엇을, 왜, 얼마 동안 보관하는지

## 상태별 화면

- 업로드 중: 진행률, 취소
- 대기·처리 중: 단계 표시, 예상 시간
- 완료: 미리보기, 저장, "다른 크기로 다시 만들기"
- 실패: 이유, 해결 방법, 다시 시도
- 빈 상태: 예시 파일로 체험하기
- 하이라이트 수집 중: 연결 상태, 끊기면 재연결 중 표시
